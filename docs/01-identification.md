# 01 数据采集与 Kp/Kd、时延辨识

## 先固定实验条件

记录固件版本、J1–J7 顺序和符号、安装姿态、抓手/IMU/相机等附件、URDF/MJCF 版本、MIT 模式、目标速度和前馈、命令与反馈频率。此次实验固件为 1.21，MIT 命令约 50 Hz，原始反馈约 200 Hz；附件质量进入模型。每条命令和反馈保存 SocketCAN 内核时间戳，并记录使能、保护和失能状态。试验先在 actor 关闭时做当前位置保持和小阶跃，再扩展到多姿态、多频率和留出验证。不要把触发安全停机的不完整轨迹混入拟合。

2026-10-23 正式完整采集覆盖静态 840 s、多频 385 s、恒速 336 s，以及独立多关节验证 136 s。静态数据筛选低速度及小跟踪误差；多频数据用于区分相位和动态响应；留出轨迹只在模型选择后评估。原始数据与完整方法见本机 `nero_identification/RESULTS_20261023.md`。

## 有效增益和时延模型

逐轴使用实际发送的 MIT 目标与测得的同帧位置、速度、电流推算扭矩：

```text
tau(t) = alpha*Kp*[p_des(t-Delta)-q(t)]
       + beta*Kd*[v_des(t-Delta)-dq(t)]
       + tau_ff(t-Delta) + bias
```

扫描候选 `Delta`，每个候选下线性拟合 `alpha`、`beta`、`bias`，比较仅命令项延迟与整条控制律延迟，并用留出频段/轨迹评估。采集时前馈为零，不能据此校准前馈系数；`beta` 主要反映速度反馈项，不能自动推广到独立速度目标输入。`tau` 是 SDK 按电流换算的扭矩，并非独立测力仪的绝对真值。因此乘数是该姿态、激励和扭矩刻度下的**有效乘数**。

## 正确解读“时延”

旧固定目标 J2 小阶跃实验中，命令提交到 CAN 本地回显的中位数约 14.75 ms，回显到可见反馈响应约 13.91 ms，合计中位数约 27.63 ms。这个合计含发送调度、物理运动和反馈可见性，**不是纯死区延迟**。本次拟合表中的 5.5–10 ms 是命令与电流反馈的最佳对齐偏移，包含采样与传输等效应；CAN 本地回显也不是电机内部应用确认。没有同步的设备内部时间戳，不能拆出精确内部执行时延。

最终成功的限位版训练虽然继承了执行器时延参数字段，但 `actuator.enabled=False`、`randomize_actuator=False`，故未实际注入逐轴通信/反馈时延。训练动作每 20 ms 生成，PhysX 每 5 ms 更新一次；目标限速和动力学响应会造成表观滞后。不要把辨识的 8 ms 中位偏移、20 ms 周期及 27.63 ms 综合响应相加作为训练延迟，否则容易重复计数。
