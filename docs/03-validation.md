# 03 验证顺序与迁移检查

## 从离线到实物

1. **冻结资产与语义。** 保存 checkpoint、训练完整配置、URDF、辨识 JSON、策略导出和 SHA256。核对关节顺序、符号、home、末端工具偏移、球心与姿态约定，确认部署动作语义和训练完全相同。
2. **仿真固定目标测试。** 在 home 与至少一个伸展姿态，以无噪声确定性 actor 回放完整保持窗口。与固定关节目标对照。共同报告末端误差、每轴目标/位置高频 RMS、原始请求变化、限速占比、反向率、关节极限余量；不能用单一低抖动指标接受“完全不动”的退化策略。
3. **导出和映射对照。** 用相同观测比较训练 actor 与 TorchScript 输出；逐步比较训练/部署的 16×39 观测、初始姿态过渡、绝对角请求、余量裁剪和每 20 ms 限速。最终部署包曾测得 64 组导出输出最大差为 0，400 步训练/部署目标角最大差约 `1.07e-7 rad`。
4. **实物 actor 关闭验收。** 先只读确认 CAN、固件与七轴反馈，再做测得姿态保持、5 s 增益渐变和 5 s 增益保持。增益换算后，维持相同实测姿态所需 MIT 目标可与训练的重力平衡目标不同；启动条件应检查实测 `q,dq`、目标与实测角的包络及限位余量，不能只比较两个控制器的目标角字面值。
5. **短时 actor 到完整任务。** 现场值守并保留急停。先短时验证 home、再验证目标移动、保持和返回，最后才做 60 s 自动采样。每次保存 raw/request/issued/echo/feedback 与时间戳，验证输出 CAN 相邻目标步长及预测限位事件。任何保护触发后先分析日志和失能结果，不直接放宽阈值。

## 本次验收已知边界

最终部署包的离线 20 s CPU PhysX 回放记录 0 次重置、0 次预测限位事件和 0 次目标余量违规，平均末端位置误差约 0.0716 m；它验证的是离线轨迹，不代表全工作空间的实物保证。用户随后报告该版实物效果很好。本文没有取得完整多姿态、多负载、长期运行的量化验收数据，不应写成已证明全场景无抖动。

## 再次迁移时核对

| 项目 | 此次案例设置或要求 |
|---|---|
| 训练与部署频率 | 50 Hz；物理仿真子步 5 ms |
| 动作接口 | 七关节绝对位置目标；每拍 J1/J2 ≤0.03 rad，其余 ≤0.04 rad |
| 观测 | 16 帧 × 39 项；关节、上一动作、末端及目标要同义 |
| 训练显式时延 | 关闭执行器随机化；不能误读继承配置中的未启用时延字段 |
| 硬件增益 | 从固定的辨识文件按轴换算，先增益保持，勿只看模型文件名 |
| 关节保护 | J7 额外目标余量；反馈速度预测极限，部署看门狗和停机流程 |
| 可追溯性 | checkpoint、配置、URDF、辨识系数、导出策略的哈希一致 |

以上数值属于这次案例，移植到其他硬件或不同抓手负载时需重新辨识、回放和验证。
